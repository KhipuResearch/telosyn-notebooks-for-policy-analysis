# ADR 0008 — The Public Distribution and Its Layout

- **Status:** Accepted, executed
- **Deciders:** Telosyn, Inc. (owner)
- **Date:** 2026-10-15

## 1. Title

This repository is the public distribution of the Telosyn Notebooks for Policy Analysis. It is
built from the private source of record, `krl-tutorials`, and restructured as a
reproducible research portfolio: numbered projects, a `src/` package, a
documented data lifecycle, generated project READMEs, a citation file, a
Makefile and a CI workflow that installs exactly what the README says. It is
proprietary. It is a data-methods portfolio, and it is laid out so that a
causal-inference track can be added as further numbered projects without
reorganisation.

## 2. Context

Two framings were available and they were not the same thing.

The portfolio conventions this layout follows were written for **causal
inference** — randomised experiments, difference-in-differences, regression
discontinuity, instrumental variables, double machine learning — with a
per-project template of *treatment, outcome, estimand, identification strategy,
DAG*. The corpus contains none of those designs. Checked notebook by notebook:
no DiD, no RD, no IV, no matching, no DML. OLS appears in six notebooks, used
descriptively. D30's "estimand" is a simulated truth for scoring; D33's is a
ratio of two medians. No notebook estimates the effect of a treatment on an
outcome.

What the thirty-three notebooks are is a **data-methods** portfolio: for each of
eighteen public sources, what it measures, what it withholds, and the specific
conclusion it cannot carry. Forcing that into a causal template would have
produced thirty-three READMEs reading "not applicable" under every heading
that matters, in a repository whose name promised the opposite.

The owner chose the data-methods framing, with the layout left open for a
causal track later.

**On the name.** The first build carried the README's existing title, *Khipu
Methods Corpus*. It was renamed *Telosyn Notebooks for Policy Analysis* before
first push, on proprietary grounds: the name now matches the owner the licence,
the citation file and every header already name, so attribution is consistent
across the record; Khipu℠ is a service mark for the analyst workspace, and a
repository of notebooks is a work rather than a service, so the corporate name
keeps the mark's use controlled; and under the `KhipuResearch` organisation the
Telosyn name prompts the ownership question the README's first line answers. The licence stays proprietary under ADR 0005; the working
folder's "Open-Source" was dropped from the name because it was not true.

## 3. Decision

| Convention | How this repository meets it |
|---|---|
| Numbered projects, unmistakable order | `projects/01-fundamentals` … `08-culture-society`; a causal track begins at `09-` |
| Notebooks separated from reusable code | `src/krl_tutorials_data/`, src-layout, the only importable tree under `src/` |
| Per-project README on one template | Generated by `scripts/build_project_readmes.py` from each notebook's title, objectives, provenance and limitations; a test fails on drift |
| Data lifecycle with provenance | `data/README.md` generated from the forty provenance records; `data/schemas/` documents the record; `data/fixtures/` points at the recorded responses the suite runs on; raw/interim/processed are ignored |
| Reproducibility signals | `pyproject.toml` with the dependencies the code actually imports; `Makefile`; `.github/workflows/test.yml` installs `'.[notebooks,test]'` on 3.11 and 3.12; seeded randomness; `pytest` |
| Repository-health files | `LICENSE`, `CITATION.cff`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md` |
| Root README as landing page | Positioning line, project table, rules, reproduce block, methodology, tools genuinely used, contact |

**What was deliberately not done.** No per-project `src/`, `reports/` or
`references/` directories: the reusable code is one shared package, and empty
scaffolding is the pitfall the conventions themselves name. No per-variable data
dictionaries: the corpus retrieves published tables rather than constructing
analytic samples, so each retrieval's `variables` field — the publisher's own
labels for the codes pulled — is the dictionary of record, and `data/schemas/`
says so rather than inventing one. No "selected results" figures yet; which
three figures represent the work is the owner's choice.

## 4. What the restructure changed, mechanically

- `notebooks_v2/<section>/` → `projects/<section>/` with hyphenated names; the
  `Dxx_` notebook directories are unchanged because the handbook and gates
  cite them.
- `krl_tutorials_data/` → `src/krl_tutorials_data/`; every notebook's
  root-discovery block and `sys.path` insert were rewritten through the
  notebook JSON, not by text substitution — a first attempt by substitution
  wrote an unescaped quote into thirty-three notebooks and broke every one.
- The handbook, migration record and source map moved to `docs/` under plain
  names, and the paths they cite were re-anchored.
- `tests/test_retirement_basis.py` now finds the external archive automatically
  (`KRL/backups/` is two levels up from this repository) and runs instead of
  skipping.

## 5. Findings along the way

- `pyproject.toml` named four private KRL distributions as runtime
  dependencies, three imported by nothing and the fourth only through a code
  path no notebook calls, while omitting four packages the code does import.
  Fixed in the source of record (`bd70452`) with three tests that hold it.
- `tests/test_leak_check.py` imports `pyyaml`, which no extra provided; the
  CI-dependency gate caught it once the workflow installed the documented way.
- The pre-commit configuration referenced a secrets baseline and two scripts
  that did not exist, so `pre-commit install` failed. Replaced with hooks that
  run on a clean checkout.
- `~/Desktop` and `~/Documents` on the build machine are under live file sync.
  Extracting two hundred files produced 219 and then 178 conflict copies
  (`name 2.ext`) within a minute, and `EDEADLK` from the filesystem. That is
  also where the 55 `copy` and ` 2` files in the retired archive came from.
  Building a git repository under a syncing folder will keep doing this; the
  recommendation is to exclude the GitHub tree from sync.

## 6. Consequences

1. The public repository and `krl-tutorials` are now two trees. Changes to
   the corpus are made in the source of record and re-exported; the export is
   `git archive` plus `scripts/restructure.py`'s mapping, and should be scripted
   before the second export rather than repeated by hand.
2. A reader who follows the README gets a working install, a passing suite of
   1,579 tests, and every result readable without a key.
3. A causal track, when written, is `projects/09-…` onward with the same
   generated-README discipline, and its per-project template can carry the
   fields the data-methods projects do not need.
