# Contributing

Thank you for reading closely enough to want to. Here is what is welcome, what
is not, and why.

## What is welcome

**Questions and discussion.** Use
[Discussions](https://github.com/KhipuResearch/telosyn-notebooks-for-policy-analysis/discussions)
for anything about a notebook's reasoning, a source's behaviour, or a method
choice.

**Defect reports.** Use
[Issues](https://github.com/KhipuResearch/telosyn-notebooks-for-policy-analysis/issues)
for something that is wrong: a figure in the prose that does not match the
notebook's stored output, a provenance digest that no longer replays, a claim
the source cannot support, a gate that fails a correct notebook, a broken link.
Name the notebook, the cell and the number. An issue that can be reproduced is
acted on; "the results look off" is not something anyone can act on.

**Attempts to break a claim.** Every release gate in `tests/test_gate_*.py`
exists because someone found a way a notebook could read as authoritative while
being wrong. If you find another, that is the most useful issue you can open.

## What is not accepted

**Code contributions, including pull requests.** The Software is the property
of Deloatch, Williams, Faison & Parker, LLLP, licensed exclusively to Telosyn,
Inc., under a proprietary licence that does not permit derivative works. A pull
request is a derivative work, and accepting one would require a written
assignment of rights that the repository is not set up to collect. Unsolicited
pull requests will be closed without review, with a pointer to this file. This
is a consequence of the licence, not a judgement of the work.

If you want to propose a change substantial enough to be worth the paperwork,
write to contact@telosyn.co and describe it.
